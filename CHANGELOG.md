# Changelog

All notable changes to SmartLists are documented here.
Format based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), versioning follows [Semantic Versioning](https://semver.org/).

## [3.9.6] – 2026-11-14

### Added

- Tap **👥 shared** in the list header to see who the list is shared with and with which rights (read only;
  changing stays in the gear of the list).
- README: animated demo at the top (typing `Milk 2 l 1,19€ @REWE *Anna #organic` → store, person and tag badges,
  price and category), a highlights table and the 3.9 changes; all existing sections and images stay. The GIF is generated by `scripts/make_demo_gif.py` (English and German).

### Fixed

- *Origin badges → colour per source list* in the list window: the colour pickers were squeezed into thin lines.
- Sidebar page: list chips no longer repeat the group name – "Liste Max" under *Lists* is shown as "Max" (also
  "HA Smartlists …" and "Notes …" prefixes). Lists taken over from the app with a German/Polish/Spanish/Italian
  "Liste/Lista …" name get the plain name, too.
- Wiki: references to the old *Configure* menu point to the general settings now.
- README and wiki state that the HA SmartLists Android app is not published yet (everything works without it).

## [3.9.5] – 2026-11-14

### Added

- **Plain list** (*⋯ → Settings of this list → Plain list*), e.g. for the hardware store: no categories, no
  suggestions or "bought often", no remembered words, units or prices. SmartLists remembers **nothing** from such
  a list – "wood" typed there never shows up in any other list, not even in lists set to *from all lists*. A price
  typed into the text stays in the text. Badges and quantities still work. Also works for a combined list.

## [3.9.4] – 2026-11-14

### Added

- **Categories off per list** (*⋯ → Settings of this list → Categories automatically*): no category groups,
  symbols or category sort for that list – and none while typing (no category chip, no picker).
- **"Bought often" and suggestions per list** (*… → Bought often & suggestions*): by default only what was
  added to **this** list; a **combined list** shows what was bought in its **source lists**; or switch a list to
  *from all lists*. SmartLists now counts per list where an item was added. History from before 3.9.4 has no
  list and keeps appearing everywhere, so nothing disappears. Due items (and *add due items automatically*)
  follow the same scope.

### Changed

- *Settings → Devices & services → SmartLists → Configure* only shows **Run setup again / start from scratch** and
  **Open settings**, which jumps to the settings on the SmartLists page (`/smartlists?settings=global`) – everything
  is there, complete and searchable.

### Fixed

- Items added to an own list from the card were counted twice in the history.

## [3.9.3] – 2026-11-14

### Added

- **Sidebar page as an app on the home screen (PWA):** 📲 in the toolbar → pick a list and "open straight in
  shopping mode" → *Install* (Chrome/Edge) or the steps shown for Android and iPhone. The icon opens
  `/smartlists?app=1&list=…&shopping=1` full screen, no extra app needed. On the page SmartLists swaps the
  web-app manifest for its own (name, icon, start list) and restores Home Assistant's when you leave. Hidden in the
  companion app and when already running as an app.
- **Stores & zones: warning for a duplicate zone name.** Creating a zone whose name already exists (e.g. a second
  "REWE") asks: keep the name or rename the new zone. Zones with the same name are shown with their entity ID.

### Fixed

- **Sidebar page sometimes showed a different list than the one chosen.** While Home Assistant or the
  integration was (re)loading, the chosen list was briefly missing; the page then picked the first list and
  remembered that. Now the choice is kept and only the display falls back until the list is back.
- New zone with a name that already existed: the store was linked to the old zone instead of the new one.

## [3.9.2] – 2026-11-14

### Added

- **Repairs: app lists not yet taken over.** A list of the HA SmartLists app (`todo.ha_smartlists_*`, e.g. in
  Local To-do) that is not yet a SmartLists list now shows up under *Settings → Repairs*. **Fix** → choose the
  owner (suggested: the user who paired the app) → the list is taken over as an own SmartLists list with all
  items, notes and checkmarks. The old list stays unchanged, as with *Take over lists*. Note lists are not
  reported (they stay in Local To-do on purpose); lists already taken over – also before this version, matched by
  name – are not reported either. Ignoring the hint in Repairs works as usual.

## [3.9.1] – 2026-11-14

### Changed

- **Shopping mode: tap the whole row to check off** – editing is locked there, so a slip can no longer rename
  an item (no item menu via long press/double click, no edit, no quantity stepper, no dragging; an open edit is
  closed when shopping starts). Leave the shopping mode to edit.
- **Undo bar for 3 seconds** at the bottom after every check-off in shopping mode (also when checked items stay
  visible) – catches mistaps.
- *Large rows* in shopping mode stays switchable (*For me → Shopping and scanning*); the help text now says that
  off keeps the normal size.
- Public address for links: the port is optional – default 8126, *change* shows the field.

## [3.9.0] – 2026-11-14

### Added

- **Share links without revealing your Home Assistant address**: *Settings → Global → Sharing and permissions →
  Public address for links* – choose *Home Assistant address* (as before), **Cloudflare Quick Tunnel** or **own
  proxy / tunnel**. For the last two SmartLists runs a small server of its own (default port 8126) that serves
  only the share page and the share API – never Home Assistant itself. The tunnel uses an existing `cloudflared`
  (PATH, `/config/cloudflared`, `/config/bin/cloudflared`); SmartLists does **not** download it, the setting
  shows where to get it instead. If the chosen way is not ready, no link is created (no silent fallback to the
  HA address). Links whose tunnel address has changed since are marked in the card.
- **Extras** (*Settings → Global → Extras*): switch **notes** and the **meal plan** on or off. Meal plan off
  hides the sidebar tab, the ⋯ entry, the dashboard view and disables the calendar; planned dishes are kept.
- Docs: SmartLists lists work directly with the **home-screen to-do widgets** of the official Home Assistant
  apps (Android and iOS).

### Changed

- Setup assistant, step *Extras*: notes and meal plan are **off by default** for a tidy start (running the
  assistant again shows the current state). Existing installations keep their settings.
- The share page loads its data relative to its own address, so a proxy under a sub-path works.

## [3.8.3] – 2026-11-13

### Added

- **Each origin badge has its own colour**: every source list of a combined list gets a different colour
  automatically; change it per source list in the card (list window → *Origin badges*).
- **Items from other cards are recognised**: text such as `2x Butcher's Burger Buns (REWE) - 0,99 €` (written by
  e.g. the offers card `custom:discounts-card`) now shows quantity (`2x`), a store badge (`(REWE)`, known stores
  only) and the price (`- 0,99 €`, per piece) instead of plain text. The stored item text is not changed;
  editing shows the cleaned-up text.
- A price with a leading dash (`Cola - 1,5 €`) is recognised when typing, too.

### Changed

- *Origin badges* in the card's list window: changes are collected and saved with **Save** (before, every click
  saved and reloaded the list at once, so several source lists could not be picked in a row).
- The origin badge no longer shows a symbol (it looked like a "-") and leading/trailing separators in list names
  are dropped.

## [3.8.2] – 2026-11-13

### Added

- **Origin badges of combined lists** (the chip such as "Admin Angebote"): choose what it shows – the list name,
  the **owner** of the source list, or **"Owner List"** – and from **which source lists** there is a badge at all.
  Set when adding/configuring the combined list or in the card (list window → *Origin badges*; admins and the
  owner). The same text is used in Home Assistant's own to-do view. Default: unchanged (list name, all lists).

## [3.8.1] – 2026-11-13

### Fixed

- Validation (hassfest) failed on a translation key (`__all__`) of the owner selector added in 3.8.0; the key is
  now `everyone`. A new test checks all translation keys against the hassfest rules.

## [3.8.0] – 2026-11-13

### Added

- **Owner and sharing for combined lists**: choose an owner and who may edit, check off or only view – when
  adding/configuring a combined list, or in the card (gear → *Owner*, *Sharing*). Without an owner ("— everyone")
  a combined list stays visible and editable for everyone, as before. Enforced in card, sidebar page, app and for
  HA services. Combined lists taken over from the app now belong to the account the app is paired with.
- Card: admins and owners can change the owner of own lists in the list window (the list moves to the new owner's entry).

## [3.7.0] – 2026-11-13

### Changed

- **Own lists are grouped per owner** on the integration page: one entry "Own lists · Julia" with one device
  holding all her lists, instead of one entry per list. ⚙ on the entry → pick a list → rename, sharing, new
  owner (the list moves to that owner's entry) or delete. *Add own list*, the sidebar ＋, the setup assistant
  and *Take over lists* put new lists into the owner's entry automatically.
- Existing own lists are **moved automatically** on update – entity IDs, items, sharing, automations and
  dashboards stay the same. (If the Home Assistant version cannot move entities between entries, the lists
  stay as they are and keep working.)

## [3.6.1] – 2026-11-13

### Fixed

- **Own lists (incl. lists taken over): checking off, adding, renaming and deleting did nothing** on newer
  Home Assistant versions. HA now stores the time of the current request as a number instead of a date;
  the permission check failed on that. Both formats work now.

## [3.6.0] – 2026-11-13

### Added

- *Take over lists*: **note lists** (e.g. notes of the app in Local To-do) can be taken over too – *as notes*
  (new SmartLists note list owned by you, titles, texts and checkmarks; encrypted notes are copied as they are)
  or as a normal list. Other users' notes are not offered.

### Fixed

- Adding an **own SmartLists list** (e.g. one taken over from Local To-do) as a source of a combined list failed
  with "Combined lists cannot be nested". Only combined lists are blocked now – they are also no longer
  offered in the list picker.

## [3.5.2] – 2026-11-13

### Fixed

- **Taking over several lists at once**: only the first new list got its entity – the integration was reloaded
  once per new list and the reloads overlapped. Several changes in quick succession now cause a single reload.
  Lists already affected get their entities after reloading the integration (⋮ → *Reload*) or restarting HA.
- New lists taken over from the app get readable names ("HA Smartlists Angebote" → "Angebote",
  "ha_smartlists_list_barcodes" → "Barcodes").

## [3.5.1] – 2026-11-13

### Added

- Every SmartLists list now appears as a **device below its entry** on the integration page – combined lists
  with their source lists ("Combined from: …"), own lists as "Own list". *Visit* on the device opens the list
  directly on `/smartlists` (`/smartlists?list=todo.…`). Combined lists from the app stay linked to the app's device.

### Fixed

- Lists that were just created or taken over did not appear on `/smartlists` until the page was reloaded
  (the list overview was fetched while the integration was reloading and not refreshed afterwards).

### Changed

- Input field example is generic and per language ("e.g. 2 kg apples @Store", "z. B. 2 kg Äpfel @Markt" …)
  and uses the store character of your naming convention instead of a store brand.
- *Take over lists*: each list shows where it comes from (Local To-do, Shopping list, Google Tasks, …).
- *Take over lists* never changes the old lists any more: they are always kept (options *empty* and
  *delete completely* removed). Afterwards a message lists them and asks you to delete them yourself once
  the new list is fine (and to add the new list to combined lists first).

## [3.5.0] – 2026-11-13

### Added

- **Take over existing lists** (*Global → Voice, backup, defaults*, admins): turn one or more to-do lists
  (HA shopping list, Local To-do, other integrations) into own SmartLists lists with items, notes and
  checkmarks – one list each or all into one (origin optionally as `*Person`/`#tag`). The old list can be
  kept, emptied or – for Local To-do – deleted; a warning appears if it is a source of a combined list.

## [3.4.0] – 2026-11-13

### Added

- **Notification targets**: send to **one or more** targets instead of a single companion app device –
  any `notify.*` service (companion app, Telegram, e-mail, Signal, groups …), `notify.*` entities
  (`notify.send_message`) and, for admins, **custom services** with JSON data (e.g.
  `telegram_bot.send_message` with `{"target": …}` or a script; `{title}`/`{message}` placeholders).
  A failing target does not stop the others; the test message reports per target. Existing settings are
  taken over automatically.

### Changed

- Badges and colours: the first colour field is now labelled *Background colour* (next to *Text colour*).

## [3.3.1] – 2026-11-13

### Fixed

- **Notifications about other people's changes never arrived** (only the test message did): the delayed,
  batched send ran outside Home Assistant's event loop and was dropped. It now runs in the event loop.
- Notifications limited to a **combined list** now also fire for changes in its source lists.
- The hourly check for *Repairs* hints ran the same way and now runs in the event loop as well.

## [3.3.0] – 2026-11-13

### Added

- **Select several items**: *Select* in the item menu or *⋯ → Select several*, then move, copy, check off
  or delete all marked items at once (with undo).
- **Meal plan on the sidebar page**: tabs *Lists* | *Meal plan* on `/smartlists`; the week plan is shown
  right on the page with a choice of the list for the ingredients. Also available as a card (`view: mealplan`).

### Fixed

- A price in the item text (`Milch 2 l 1,19€ @REWE`) was not taken over when something followed it (e.g. a
  store); it is now recognised anywhere in the text, shown in the preview and also when editing an item.
- Combined lists taken over from the app are attached to the app's device with full device details, so
  the list is created reliably and shows up on the device page and on `/smartlists`.

## [3.2.0] – 2026-11-13

### Added

- **Setup assistant from the integration**: the success message after adding SmartLists and
  *Configure → Setup assistant* link straight to it (`/smartlists?setup=1`). After *start from scratch*
  in Configure, a link opens it as well, and it appears the next time an admin opens SmartLists.
- **Badge colours**: besides the colour (background), an optional **text colour** per kind and per badge.
- **Notifications**: *Also for my own changes* and a *Send test message* button; failed messages are logged.
- **Meal plan**: changes are kept until **Save** (asks whether to add the ingredients to the list) or
  *Add ingredients to list*.
- Autocomplete: ↓ reopens the suggestions, the selected entry is clearly highlighted and scrolled into view.

### Changed

- Shopping mode for one store shows items without `@store` too – now on by default.
- Aisle order: rows can always be dragged by the handle ⠿, no extra sort mode; ▲ shows the right arrow.
- Clicking next to a window only closes it if nothing was typed or changed in it (no more lost templates).

### Fixed

- Badges in the list ignored the symbol and colour set under *Badges and colours* (e.g. `#test`, people).
- ⋯ menu opened far below the button on short lists; sort row had a duplicate icon and a misplaced arrow.
- Symbols in the icon picker were not centred; *＋ Dish* in the meal plan was cut off.
- Changes made through a combined list are attributed to the right person (notifications, history).

## [3.1.0] – 2026-11-13

### Added

- **Start from scratch** (General settings → Global → Voice, backup, defaults, and Configure in the
  integration): choose what to reset – settings (notation, badges, stores and zones, aisle orders,
  permissions, voice, list display, keyword packs), learned data (categories, history, statistics,
  prices, expenses, templates, meal plan), all share links and/or combined lists – then the setup
  assistant opens. To-do lists and their items are never deleted; personal settings stay.
- *Run setup again* now sits next to it and keeps all data.

## [3.0.0] – 2026-11-13

### Added

- Sidebar page: the list overview at the top is **collapsed by default** – one line with the selected
  lists and *All lists ▾*; expand to see all groups (remembered per browser, always open while sorting).
- **Barcode scan uses the companion app's own scanner** (Android/iOS) when available – much more reliable
  than the camera in the app's web view. Non-product codes (QR etc.) are rejected with a hint, *Type the
  number* opens manual entry. In browsers the camera/number dialog stays.
- **Scanner settings** – per user (*For me → Shopping and scanning*): target list (this card's list or any other) and
  whether scanned products go into the input field or are added directly. Global (*Voice, backup,
  defaults*): which lookup services in which order – Open Food Facts, Open Beauty Facts, Open Pet Food
  Facts, Open Products Facts, UPCitemdb, or your own service (URL with `{code}` + JSON field for the name).
- **Meal plan**: dishes (templates) per day, *Add ingredients to list* for the whole week, calendar entity
  *SmartLists Meal plan*; optional **Mealie** import (recipes of the Mealie meal plan become templates).
- **History per item** (long press → History): who added, checked off, reopened, renamed or deleted it, and
  when – including the app, automations and shared links.
- **Shopping dashboard** with one click (Global → Voice, backup, defaults): lists, meal plan, statistics.
- **Diagnostics** download (no item texts, tokens or names) and hints under **Repairs**: missing source list
  of a combined list, devices not synced for 30 days; share links of deleted lists are removed.
- **Slimmer card header**: search, undo, shopping mode and ⋯ (sort, import, templates, meal plan, settings).
- More automated tests (permissions, link limits, meal plan, Mealie ingredients, item history).
- **Setup assistant** on first opening (admins): lists (use existing, combine or create new), stores,
  notation (`@` `*` `#` with live example), language (keyword packs), people (permissions for a new own
  list) and extras (notifications, Assist, prices, barcode lookup, link sharing) – every step can be
  skipped, all in six languages. Not shown to installations already in use; *Run setup again* under
  Global. WebSocket `smartlists/setup`, `config.setup_needed`.
- **New settings layout**: the general settings are organised in areas – *For me* (controls, shopping and
  scanning, notifications), *Global* for admins (badges and colours, stores & zones, categories, devices
  and notes, sharing and permissions, voice/backup/defaults) and *Insights*. Wide screens show the areas
  on the left and the selected area in two columns; narrow screens show the areas first. With search.
  Calmer look without boxes.
- **Settings window per list** (⋯ → Settings of this list): name, default sort order and prices on/off for the list
  on all devices, sharing with people and sharing via link – two columns on wide screens, a sheet on small.
- **Sharing and permissions** (Global): admins decide who may create share links (admins · admins and
  owner · everyone who may edit · nobody), what a link may allow at most and the longest validity, see and
  revoke the active links of all lists, and switch off for non-admins: creating own lists, changing
  templates, assigning categories, entering prices.
- WebSocket: `smartlists/set_rights`, `share_links_all`, `set_list_settings`; `config` returns `rights`,
  `get_list` returns `settings`.

### Changed

- "Household" is now called **Global** in the settings; "phone" is now **device** everywhere (interface in
  all six languages, setup dialogs, documentation).
- New wiki page *Settings*; the pages on sharing, scanning, devices and the sidebar page were updated.

### Fixed

- **No more refresh while you edit**: background updates only redraw the list when something really
  changed (someone else checked, added or deleted items), and never while you are editing an item, typing,
  have a menu, dialog or the settings open or are dragging – they are applied right after you finish.

## [2.9.1] – 2026-11-12

## [2.9.0] – 2026-11-12

### Added

- **Live updates without reloading**: cards and the sidebar page refresh by themselves when household data
  changes (categories, packs, badges, prices, templates, aisle orders, links, notes, devices) – new
  WebSocket subscription `smartlists/subscribe`. Items were already live. Safety net for tablets/phones:
  silent reload after waking up / returning to the tab and once a minute.
- **Symbol picker** for templates and badge symbols (people, tags): grid by group, tap to preview, OK to
  apply; own symbols can still be typed.
- **Aisle order by drag & drop**: *Sort* button in the order editor, then drag the rows by ⠿ (mouse,
  finger or pen); ▲▼ stay available.
- **Remembered categories can be changed** afterwards directly in the list (Household → Remembered
  categories).
- **Shopping done** button next to the total: the "in cart" sum starts at 0 again (expenses stay booked);
  optionally reopen all checked items for lists you reuse. WebSocket `smartlists/finish_shopping`.
- **Fix wrong data afterwards**: delete single expense bookings (admins all, others their own) and remove
  items from the history/statistics (admins).
- **Create a note list** even if the app has none yet (Household → App notes, or ＋📝 on the sidebar page):
  Local To-do list `todo.ha_smartlists_notes_<name>`, owned by you.

### Fixed

- Colour pickers in *Badges & colours* no longer close on the first click – the preview changes while you
  pick, saved when the picker is closed.
- CI: Node 24 actions (checkout v5, setup-python v6), runners pinned to ubuntu-24.04; releases are now
  created automatically when the manifest version changes.

## [2.8.0] – 2026-11-12

### Added

- **Aisle order per store** (and optionally per branch/zone): shopping mode groups the list in the order of
  the store's aisles. Household → Stores & zones → 🛤️ Order.
- **Prices & expenses**: price per item (typed at the end, `Milk 2 l 1,19€`, in ✏️, or from the app's
  offers), unit price and total in the list, expenses booked when checking off, weekly/monthly/yearly
  overview per store, sensor *Expenses this month*.
- **Templates & recipes**: 📋 in the card – add with servings (quantities scaled), untick items, increase
  quantities of items already on the list; create from scratch or from the current list; Assist
  ("Put pancakes on the shopping list") and action `smartlists.add_template`.
- **Share via link / QR code** for people without an HA account: view only by default; optional "soft"
  check (marked, stays open), real check off, adding; validity 2 h – 30 days or until revoked; revoke
  any time. 256-bit keys, only hashes stored, nothing but item texts exposed.
- **Notifications** when someone else adds or checks off items – per user: phone, lists, people, quiet
  hours; bundled per minute.
- **Barcode scan** with the camera (or typing the number); names via Open Food Facts (only the number is
  sent, can be turned off) and remembered.
- **Statistics**: bought most often with rhythm, not bought for a while, shares per category and store
  (📊 on the sidebar page, tab *Statistics* in the general settings).

- **Configure → All SmartLists lists**: every `todo.ha_smartlists_…` list (from the app or the
  integration) grouped as combined lists, lists and notes, with entity ID, open items and origin.
- **Sidebar page grouped**: chips are shown in three groups – *Combined lists*, *Lists*, *Notes*. Combined
  lists reported by the app that are not connected yet appear dashed (📱) and can be connected with a tap
  (admins).

### Changed

- **Entity IDs of new lists** follow the app's scheme: own lists `todo.ha_smartlists_list_<name>`,
  combined lists `todo.ha_smartlists_list_merged_<name>` (note lists of the app: `todo.ha_smartlists_note…`).
  Existing lists keep their IDs – no automations break.
- Share links: changes via a link never alter household prices or suggestions, notifications for them
  don't include the typed text, adding is limited to 6 per minute, request bodies to 2 KB, reading to
  120 per minute; links of deleted lists (or lists that became notes) stop working immediately.
- Placeholder examples no longer contain real place names or coordinates.

## [2.6.0] – 2026-11-12

## [2.5.0] – 2026-11-12

### Added

- **Badges & colours** (⚙ → Household): style per kind (filled, subtle, outline, text only), colour and
  symbol for stores, people and tags; colour per individual badge (`@REWE`, `*Anna`, `#bio`) and a display

  `set_store_zone` accepts `zones` / `add`; `register_device` accepts `app_lists`.

### Changed

- `store_zones` values are now lists of zones (a single zone from 2.4.0 is read as a list).

## [2.4.0] – 2026-11-12

### Added

- **Stores & zones**: link stores (`@REWE`, `@Lidl`, …) to Home Assistant zones – or create a zone right
  from SmartLists at the current location (⚙ → Household → Stores & zones). In **shopping mode** a store bar
  (All | REWE · 4 | Lidl · 2) shows only the items of one store, and the store whose zone you are in is
  selected automatically. Optional: also show items without a store.
- **Keyword pack editor**: search, add, change and delete keywords of any pack in the card; create new
  packs (e.g. for another language). Built-in packs are extended through an add-on pack "<name> +" so
  updates never overwrite your changes. Downloading a built-in pack includes your additions.
- **App notes hidden**: the note lists of the HA SmartLists app (`todo.ha_smartlists_note…`) no longer
  appear as shopping lists. Admins can show them as a separate 📝 section on the sidebar page. Notes are

  offered when creating combined lists.
- **Sidebar page**: any number of lists side by side (wrapping into rows, up to 4 columns in wide layout)
  and a custom **order** – ◀ ▶ or drag the chips with the mouse; remembered per browser.
- WebSocket: `smartlists/pack_create`, `pack_terms`, `pack_update`, `stores`, `set_store_zone`, `notes`,
  `set_notes`; `register_device` accepts `notes_lists`.
